Phase	Purpose	Exit condition
0 — Freeze the architecture	Stop new Search inventions	One active Search execution lane; legacy branches evidence-only
1 — Build the complete impact graph	Know exactly what currently exists	Every Search surface and every provider reader/writer classified
2 — Establish Cotality truth	Remove guessing	Live Resource/Field/Lookup/query contract documented and verified
3 — Remove false authorities	Eliminate RESO, RealPlus and RLS-provider contamination	Required zero-occurrence checks pass

9 — Preview and production proof	Prove it outside tests	Preview → prod behavioral proof and execution state closed

This sequence should not be changed because the next failing test happens to look interesting.

Phase 6 — Move the Search surfaces systematically

Do not jump around based on whichever endpoint currently fails.

Use this dependency order:

Order	Workflow	Required result
1	Sale Search	Complete canonical Search E2E
2	Rental Search	Same engine, Rental-specific criteria
3	Public Search	Becomes restricted/compliant consumer of Search foundation
4	Building Search	Specialized building criteria but common provider authority
5	Saved Search	Exact SearchCriteria persistence/execution parity
6	Alerts	Uses Saved Search; never invents criteria
7	Map	Same settled universe as list
8	Similar Listings	Specialized criteria over same Search/provider primitives
9	Agent Listings	Agent constraint over common provider layer
10	Suggestions/autocomplete	Lightweight consumer, not another provider implementation
11	Workbench / Compare / Reports	Consume selected canonical results
12	CMA	ComparableCriteria over corrected Search foundation
13	Open House	Specialized resource, shared Cotality authority

This is how the “12 Search systems” get reduced without destroying useful brokerage functions.

Phase 7 — Only then delete duplicate Search code

This is critical.

Do not leave old implementations “for safety.”

old route helper
old mapper
old query builder
old provider client
old enum table
old browser-side filter implementation
old result reconciler

gets removed.

And removal has a negative test proving the obsolete path cannot silently return.

Phase 8 — Fix the exposed 12 Cotality/form defects

The current red provider/form mismatches are useful.

They should not be bypassed just to turn CI green.

Each mismatch gets handled through:

actual Cotality Field
        ↓
actual Lookup values
        ↓
current Mallan field
        ↓
business requirement
        ↓
correct UI/storage behavior

For example, if Cotality has hundreds of InteriorFeatures, the answer is not to force it into Yes/No just because an old form did.

And if NYC Rent Stabilization is a Mallan business criterion rather than Cotality's AvailableLeaseType, it remains Mallan-owned rather than fabricating a provider mapping.

That pattern should resolve all twelve.

The anti-loop rule

This is the most important operational change.

Once something has been classified and proven, it goes in the continuous execution state as:

CLOSED
evidence:
commit:
tests:
preview:
downstream:

Claude is not allowed to reopen it from an older branch, handoff or chat unless new current-head evidence proves a regression.

Old chats and old PRs can identify a possible defect.

They cannot override current verified code.

That single rule would eliminate a large portion of the repeated work you have been seeing.
