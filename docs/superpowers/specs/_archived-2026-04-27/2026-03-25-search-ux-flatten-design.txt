SEARCH UX FLATTEN — DESIGN SPEC
================================

Date: 2026-03-25 (updated with external audit findings)
Sub-Project: 1 of 3 (Search UX Flatten → CMA Engine → Pricing Suggestions)
Scope: CRM search (public/crm/index-built.html) — navigation restructure, form
       deduplication, rental field wiring, sticky search bar, CRITICAL bug fixes,
       accessibility fixes
Prerequisite for: CMA Engine (Sub-Project 2) — CMA reuses the same filter components


PROBLEM STATEMENT
-----------------

The CRM search has 5 navigation layers before reaching search criteria (Header → Search Type → Property Type → Mode → Sections). This feels fractured. Additionally, 40+ rental-specific fields are stubbed (HTML exists, JS unwired), 3 nearly-identical basic mode forms duplicate ~2,000 lines, and the search button requires scrolling to the bottom of the form.


GOALS
-----

1. Fix 8 CRITICAL data-mapping bugs (C1-C8) that block correct search results
2. Flatten navigation from 5 layers to 2
3. Wire all rental stub fields + advanced mode wiring gaps
4. Deduplicate 3 basic forms into 1 shared form
5. Add sticky search bar (always visible)
6. Fix accessibility violations (labels, keyboard nav, DRP mobile)
7. Prepare nav structure for CMA tab (Sub-Project 2)
8. Preserve all existing working functionality (including saved searches)
9. Extend scanner to handle <select> and radio groups (not just checkboxes)
10. Add unit tests, E2E tests, and mapping contract tests


NON-GOALS
---------

- CMA search/results (Sub-Project 2)
- Pricing suggestion engine (Sub-Project 3)
- Public frontend search (app/search/page.tsx)
- Redesigning the results display (5 view modes stay as-is)

RELATIONSHIP TO SUB-PROJECTS 2 & 3
================================================================================

This spec creates the foundation:

  CMA Engine (SP2):
    Reuses shared search filter components. CMA tab replaces placeholder with
    3 date pickers + CMA results renderer. data-show-on="cma" sections added
    without touching existing search code.

  Pricing Suggestions (SP3):
    Builds on CMA data. Uses same filter criteria to find comps, then calculates
    price tiers (conservative / recommended / aspirational).

  CMA Report Output — Two Tiers:

    SUMMARY CMA (Client / Buyer / Seller):
      Summary cards + grouped tables (address, price, beds, baths, sqft, $/sqft,
      DOM, status) + segment analysis by neighborhood + charts. Clean, digestible.

    FULL CMA (Appraiser / Detailed Client):
      1. Summary Section
         - Active Listings summary (count, avg price, avg $/sqft)
         - In Contract summary (count, avg price, avg $/sqft)
         - Sold Listings summary (count, avg price, avg $/sqft)
      2. Active Listings — Full Detail
         Each listing: all photos, floor plans, financials, building details
      3. In Contract — Full Detail
         Each listing: all photos, floor plans, financials, building details
      4. Sold Listings — Full Detail
         Each listing: all photos, floor plans, close price, listing discount, DOM
