## The Cotality findings

The **central provider conclusion is supported**.

The September Search evidence records a direct live Cotality study. It found **18 entity sets**, 17 metadata resources, 1,456 fields, 181 enums and 31 navigations. More importantly, the live `Field` resource showed 243 Property fields with a `LookupName`, with 61 of those using a LookupName different from the field name. Its resulting rule is:

**Field → LookupName → Lookup rows**

rather than assuming a field's valid values can be obtained by looking up a `$metadata` EnumType with the same name.

That means the prior session was correct about the **architectural defect**: `$metadata` type information and the provider's field-published vocabulary are not interchangeable.

The Search branch's independent live checkpoint also records the provider's StandardStatus tokens, including **`Canceled` with one L**.

However, I am **not independently certifying these later transcript numbers as current facts**:

* 621 published field vocabularies
* 325 with no EnumType
* 339 missed by old indexing
* 30 shared EnumTypes
* 27 divergent value sets
* Trestle 5.9
* 280/min and 8,400/hour quota

Those may have been obtained by the local Claude session, but I did not find all those exact aggregate values in the durable evidence I inspected. More importantly, the Cotality connector is currently failing at its MCP tunnel with a 404, so I cannot perform a fresh live census today.

So the correct status is:

**Lookup-vs-EnumType defect = independently supported.**

**Those exact later aggregate numbers = not freshly reproduced by me.**

## The terminal-status finding is real — but the count “8 definitions” is not reliable

Current `main` still defines provider terminal statuses using:

`Closed, Sold, Leased, Rented, Withdrawn, Expired, Cancelled`

with double-L `Cancelled`.

`normalizeStandardStatus()` converts single-L `canceled` to Mallan's double-L `Cancelled`, and `computeGateColumns()` normalizes **before** evaluating terminal status. That confirms the prior session's claim that the primary writer does not miss `Canceled`.

But the daily retention route separately redeclares the raw double-L list rather than consuming the normalized canonical helper.

So the stated **latent cron exposure is real statically**.

What I would correct is the claim that there are “8 competing TERMINAL_STATUSES definitions.” Current main code search shows at least **nine listing-domain declarations or independent status sets**, before counting separately named mirrors such as `ARCHIVE_TERMINAL_STATUSES`. Examples exist in compliance status, CRM status mapping, ghost reconciliation, syndication, data retention, public filtering, feed reconciliation, RLS enforcement and the Trestle mapper.

So the **problem is confirmed; the number 8 was an undercount or definition-dependent count**.

I cannot verify the claimed current Production counts—7,591 Active, 6,975 Withdrawn, 6,089 Closed, etc.—or “zero displayed” today because those require the Production database evidence used in that prior session. I will not carry them forward as current facts.
