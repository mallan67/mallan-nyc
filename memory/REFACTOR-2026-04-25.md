## Per-PR universal rules (apply to every PR in this plan)

These rules are non-negotiable. Every PR must satisfy all of them before merge.

### 1. Branch + worktree

- Branch off `main` only. No stacking onto an unmerged refactor branch.
- Branch naming: `refactor/NN-short-description` where NN is the two-digit PR number from this plan.
- Use a git worktree to isolate the work:
  ```bash
  cd C:/Users/MayaAllan/Desktop/mallan-nyc
  git fetch origin main
  git worktree add ../mallan-nyc-prNN refactor/NN-short-description origin/main
  cd ../mallan-nyc-prNN
  npm ci   # reproducible install per package-lock
  ```
- After PR merges, remove the worktree: `git worktree remove ../mallan-nyc-prNN`

### 2. Production Verification Note (mandatory in every PR body)

Every PR description MUST include this section verbatim, filled in:

```markdown
## Production Verification Note

**Post-deploy URL to hit:** [exact URL on mallan.nyc that exercises the change]
**Metric to observe:** [Vercel logs / Neon `pg_stat_*` / response time / error rate]
**Rollback trigger:** [the specific condition that means "revert immediately"]
**Success criteria within 30 minutes:** [what must be true for the PR to be considered safe]
```

Tests-pass is necessary but not sufficient. Production must be observed.

### 3. NEON.md schema discipline

Schema-touching PRs (this plan: PRs 2, 5, 8, 9, plus parallel Workstream C):

- **One schema change per PR.** No bundling.
- **Nullable first.** Add columns/tables as nullable. Backfill is a separate PR or background script.
- **Dual-write before reader migration.** Sync writes to BOTH old JSON and new column for ≥1 sync cycle (`*/12 *` cron).
- **Migration applied manually to Neon prod BEFORE code merges.** Vercel build does not run migrations.
- **One reader at a time.** Migrate JSON readers to columns one PR at a time. Each PR rolls back independently.

PR 1 swaps in these helpers at the call sites that still hand-roll the comparison.
